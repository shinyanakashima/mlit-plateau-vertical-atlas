# 技術仕様

## この文書の対象範囲

本書は元の **PLATEAU Vertical Atlas**（`main`、本ブランチでは `?app=atlas`）の技術仕様と、LT11版も再利用する共通処理を説明します。
東京駅の配列形状・層数・性能値は東京駅エリアの例です。**鉛直3mをLT11マンション版へ適用するものではありません。**
LT11版（芝浦・立川など）の格子・追加レイヤー・仮想フロアの定義は [LT11_MANSION.md](LT11_MANSION.md#格子とzarr構成lt11版) を参照してください。

| 対象 | エリアID | 水平 `dx` | 鉛直 `dz` | 配列形状 `(z, y, x)` | T.P.格納範囲 `[下端, 上端)` |
| --- | --- | --- | --- | --- | --- |
| 元のVertical Atlas | `tokyo-station` | 2m | 3m | `(82, 256, 256)` | `[0, 246)` m |
| 元のVertical Atlas | `nishi-shinjuku` | 2m | 3m | `(90, 256, 256)` | `[30, 300)` m |
| LT11マンション版 | `minato-shibaura` | 2m | 2m | `(88, 256, 256)` | `[0, 176)` m |
| LT11マンション版 | `tama-tachikawa` | 2m | 2m | `(107, 256, 256)` | `[0, 214)` m |

両版ともZarr v3を使い、各LODの `occupancy` / `building` のチャンク形状は `(1, 256, 256)`、gzip level 6です。
チャンク形状はセル数であり、鉛直の実寸はエリアごとの `dz`（3mまたは2m）で決まります。
`ground[y, x]` は両版とも形状・チャンク `(256, 256)` の2D配列です。
LT11版は同じ形状・チャンクの `coverage[y, x]` も持ちます（同梱の東京駅・西新宿データにはありません）。
格子設定は [pipeline/areas.json](../pipeline/areas.json)、書き出しは [pipeline/atlas/store.py](../pipeline/atlas/store.py)、
生成済みデータは `public/data/<area>/atlas.zarr/zarr.json` の `attributes.grid` と各配列の `zarr.json` を根拠にしています。
解像度はブランチ全体の固定値ではなくエリアごとの設定で、LT11ブランチにも元の3m格子のデータが残っています。

## 全体構成

```
PLATEAU データカタログAPI ──► CityGML (bldg, EPSG:6697)
国土地理院 標高タイル ───────► 地表面標高 (DEM5A)
                     │
              pipeline/ (Python)
   parse ─► project (EPSG:6677) ─► voxelize LOD1 / LOD2 ─► Zarr v3 + glTF + JSON
                     │
              public/data/<area>/  (静的ファイル。R2へそのまま移せる)
                     │  HTTP Range不要・1高度=1チャンク
              src/ (React + TypeScript)
   zarrita ─► 断面 Uint8Array ─► 解析 (TS / Web Worker) ─► Canvas テクスチャ
                                                         └► Recharts
   CesiumJS ─► 建物glTF (CustomShader) + 断面クアッド + 2D/3D 経路
```

## 座標系・標高基準

| 項目 | 値 |
| --- | --- |
| 入力 | CityGML EPSG:6697（JGD2011 緯度経度 + T.P.標高） |
| 解析グリッド | EPSG:6677（平面直角座標系 第IX系、m）。`x`=東向き、`y`=北向き |
| 鉛直 | 東京湾平均海面（T.P.）からの標高。PLATEAUと地理院DEMで共通 |
| 配列順 | `occupancy[z, y, x]`。`y=0`が**北端**、`x=0`が西端、`z=0`が最下層 |
| セル | `(j, i)` は 東 `[x0 + i·dx, x0 + (i+1)·dx)`、北 `(y1 − (j+1)·dx, y1 − j·dx]` |
| 高度層 | 層 `k` は `[z0 + k·dz, z0 + (k+1)·dz)`。中心 `z0 + (k+0.5)·dz` で判定 |
| 東京駅エリア | nx×ny×nz＝256×256×82（配列順は82×256×256、dx=2m、dz=3m、T.P. 0〜246m）、原点 x0=−6,252m, y1=−35,112m |

格子の原点はdx刻みにスナップし、再実行してもビット単位で同じ結果になります。
これらは Zarr ルートの属性（`grid`, `crs`, `corners_lonlat`, `enu`）にすべて記録されます。

### Cesium上の位置合わせ

- 建物glTFの頂点は、エリア中心を原点とする局所ENU（東・北・上、m）で書き出し、glTFのY-up規約で `(E, U, −N)` として格納
- Cesium側は `Transforms.eastNorthUpToFixedFrame` をモデル行列に使い、`upAxis: Y, forwardAxis: X` を指定（既定の forwardAxis=Z では90°回転してしまう）
- 断面クアッドも同じENUフレームで描き、モデル行列の平行移動だけで上下させる（ジオメトリの再生成なし）
- 平面直角座標の格子とENUの対応はアフィン変換（子午線収差による約0.04°の回転と縮尺係数）。5×5点の最小二乗で求め、残差は0.1mm未満
- 地形なしの地球儀に建物を接地させるため、表示高さ = T.P. − （エリア内地表面標高の5パーセンタイル）。この一律オフセットは `display.height_offset_m` に記録

## ボクセル化（pipeline/atlas/voxelize.py）

値：`0`=空き、`1`=建物、`255`=判定対象外（セル中心が地表面より下）

### LOD1
`lod1Solid` の底面を平面図形、`[min(底面標高, 地表面), 上面標高)` を鉛直区間として、
セル中心が平面図形の内側にある列の、層中心が区間内にある層を `1` にします。

### LOD2（鉛直レイキャスト）
1. 建物の `boundedBy`（屋根・壁・底面…）と `outerBuildingInstallation` のポリゴンごとに、Newell法で平面を求める
2. 鉛直な面（壁）は平面図で面積がないので除外
3. ポリゴンが覆うセル中心で、その平面の高さを「交差」として記録
4. 建物×列ごとに交差を並べ、2つずつ組にして内部区間とする（入る→出る）。奇数個（閉じていない形状）は最小〜最大で埋める
5. 最下端が地表面から1.5m以内なら地表まで延長（底面とDEMの差を吸収）
6. 附属物（キャノピー等）は地表まで延長しない → 庇の下の空間が空く

これにより、超高層の低層部（基壇）と塔状部のセットバック、ピロティや大屋根の下の空間が残ります。
LOD1は建物を一つの箱として押し出すため、基壇部まで塔と同じ高さになり中層の占有を過大評価します。
一方でPLATEAUのLOD1上端が計測高さより大幅に低い超高層（東京駅エリアで6棟。例：グラントウキョウ ノースタワー LOD1上端 T.P. 95.6m／計測高さ 202.3m）があり、上空では過小評価になります。

| 断面（T.P.） | LOD1 占有率 | LOD2 占有率 |
| --- | --- | --- |
| 7.5 m | 43.6% | 43.5% |
| 31.5 m | 19.8% | 17.7% |
| 61.5 m | 17.0% | 13.0% |
| 91.5 m | 15.2% | 10.6% |
| 151.5 m | 6.2% | 8.7% |
| 181.5 m | 0.1% | 5.7% |

### 推定・簡略化の範囲
- 2mセルの中心1点で判定。幅2m未満の部材・屋上突起は欠落することがある（実データの検証では最上層の誤差は−9m〜0m）
- 地下構造・高架橋・ホーム以外の鉄道構造物・樹木・電線・看板は対象外（`bldg` のみ）
- 対象範囲外の建物は存在しないものとして扱う

## Zarr 構成

以下は**元のVertical Atlas・東京駅エリア**の例です。LT11版は同じ配列・チャンク設計で層数と `dz` が異なり、`coverage` が加わります。

```
atlas.zarr/                     zarr_format 3, group（属性に格子・座標系・出典をすべて保存）
├── lod1/occupancy   uint8   (82, 256, 256)  chunks (1, 256, 256)  gzip  fill 255
├── lod1/building    uint16  (82, 256, 256)  chunks (1, 256, 256)  gzip  fill 0（buildings.json の1始まりID）
├── lod2/occupancy   …同上
├── lod2/building    …同上
└── ground           float32 (256, 256)      chunks (256, 256)     gzip  T.P. m
```

- **各3D配列で1高度＝1チャンク**：選択LODの `occupancy` の高さ1枚（gzip後 1〜8KB）を取得すれば建物占有の断面を描ける。建物IDは同じ高さの `building` の別チャンクから取得する。東京駅のプロファイル計算では選択LODの `occupancy` 全82チャンクを、表示中の高さに近い順に6並列で取得する。`ground` やメタデータの取得は別途必要
- 空のチャンクも書き出す（`write_empty_chunks`）。SPAフォールバックでHTMLを返す静的ホスティングでも誤ってデコードしないため
- gzipはzarritaの標準コーデックで追加WASMなしに読める
- 東京駅エリア全体で約4MB。範囲を広げる場合はチャンクを `(1, 256, 256)` のタイルに分け、R2に置いても同じURL構成で読める

### Zarr-Cesium を採用しなかった理由
[zarr-cesium](https://www.npmjs.com/package/zarr-cesium) 0.3.5 を調査しました。海洋・気象のような
EPSG:4326/3857 の連続値グリッドを、カラーマップでImageryLayer（地表に貼る）やボリューム表示する用途に特化しています。
本アプリでは (1) 平面直角座標の格子を任意標高の水平面に置く、(2) 値ではなく解析結果（連結成分ID・離隔距離）で塗る、
(3) 建物モデルと同じENUフレームで厳密に位置合わせする、が必要なため、zarritaで直接読み、断面は自前のクアッドとCanvasテクスチャで描いています。

### VoxCity を採用しなかった理由
[VoxCity](https://pypi.org/project/voxcity/) 1.8 はPLATEAU CityGMLの読み込みとボクセル化に対応していますが、
立方体ボクセル（水平・鉛直同一サイズ）と「建物フットプリント×高さ」の押出しが基本で、
Earth Engine・geemap等の重い依存を持ちます。2m×3mの異方性格子、LOD2の屋根形状、255（判定対象外）の扱いが必要なため、
lxml・Shapely・pyproj だけの軽量なボクセル化を実装しました。

## 解析アルゴリズム（src/analysis/slice.ts、pipeline/atlas/analysis.py）

| 指標 | 定義 |
| --- | --- |
| 占有率 | 建物セル ÷ 判定可能セル（≠255）× 100。判定可能セルが0なら「—」 |
| 空間率 | 100 − 占有率 |
| 通行可能セル | 値0、かつ離隔条件、かつ境界帯の外 |
| 離隔 | 建物セル中心までの二乗ユークリッド距離を Felzenszwalb–Huttenlocher 法で厳密に計算（整数セル²）。`d²·dx² ≥ c²` を満たすセルのみ通行可能 |
| 連結成分 | 通行可能セルの4近傍（上下左右）連結。斜め接触ではつながらない。IDは走査順（scipy.ndimage.labelと同一） |
| 最大連結領域の割合 | 最大成分のセル数 ÷ 通行可能セル数 |
| 意味のある成分数 | 100m²（25セル）以上の成分の数 |
| 2地点の連結 | 同一高度で同じ成分IDか。最短経路はBFS、表示は見通しによる折れ点削減 |
| つながる最低標高 | 下の層から順に2地点の連結を調べた最初の層 |
| 3D経路（実験） | 8方向水平＋上下の10近傍A*。水平移動 dx·√2/dx、上下 dz×1.6。斜め移動で建物の角を切らない |

- 1断面（256²）の解析は離隔ありで数ms。東京駅の全82高度のプロファイルは Web Worker で計算し、スライダー操作を妨げない
- TypeScript実装とPython実装（scipy）を、実データ・合成データの全高度で照合するテストがある（`src/analysis/slice.test.ts`）

### 境界の落とし穴
対象範囲の外周に沿った道路があると、内部では分断されている空間が「縁を回り込むだけ」で連結してしまいます。
逆に、範囲外を通れば実際にはつながる空間が、範囲内だけでは分断に見えることもあります。
本アプリでは (1) 外周の帯（0〜40m）を解析から除外する設定、(2) 各成分が外周に接しているか（ホバー表示）を用意し、
境界に依存した結論かどうかを確認できるようにしています。

## 床の標高の推定（空中のご近所さん）

床の標高 = 地盤標高（LOD1底面）+（階 − 1）× 階高、階高 = 計測高さ ÷ 地上階数（2.8〜6.0mに制限）。
地上階数が不明（PLATEAUで9999）な建物は階高4mと仮定。計測高さは屋上設備を含むため、実際の床より高めに出ることがあります。

## 性能

- 初回表示：manifest・Zarrメタデータ・建物属性（37KB）・表示中の1チャンクで断面が出る
- 建物glTF：LOD2 約6.2万三角形・4.6MB、LOD1 約4.7千三角形・0.3MB
- 航空写真：地理院タイル z18 を1枚（2.2MB）に結合して同梱。オフラインでも中心部は表示される
- 再生中は断面の平行移動だけを毎フレーム更新し、テクスチャは層が変わったときだけ再生成。グラフは `useDeferredValue` で低優先度更新
